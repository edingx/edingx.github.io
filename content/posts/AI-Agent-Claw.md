# 从 Claude Code 到"小龙虾"，再到办公智能体平台：一条线看懂 Agent 的三次迁移

## 引子：三个阶段，其实是同一件事不断"搬家"

过去一年多，AI Agent 的演进可以看成一场迁移：

| 阶段         | 代表                                | Agent 住在哪              | 服务谁           |
| ------------ | ----------------------------------- | ------------------------- | ---------------- |
| ① 终端时代   | Claude Code、Codex CLI              | 开发者的命令行            | 程序员           |
| ② 入口时代   | OpenClaw（小龙虾）                  | 聊天软件 + 个人电脑       | 极客、早期玩家   |
| ③ 产品化时代 | WorkBuddy、QClaw、ArkClaw、CoPaw 等 | 桌面客户端、云端、企业 IM | 普通职场人、企业 |

每一次搬家，底层的"发动机"（模型 + 工具 + 循环 + 权限）没变，变的是**入口、门槛和包装**。

## 一、第一阶段：Claude Code，把"Agent 循环"带进终端

先做个小修正：把 Claude Code 称为"鼻祖"不完全准确，在它之前已有各种编程 Agent 的探索。但它确实把一套范式推向了主流：**模型直接在你的项目目录里读文件、跑命令、改代码，自己判断下一步，直到任务完成**。

这个阶段的关键词是"**可扩展**"。官方文档把扩展层拆得很清楚：CLAUDE.md 提供持久上下文，Skills 提供可重用的工作流，MCP 连接外部服务，Subagents 在隔离上下文里跑任务，Hooks 在事件触发时执行确定性脚本。

这套"Skill + MCP + Hook"的思路后来成了整个行业的通用语言，下面会看到，办公 Agent 也在用同样的概念。

OpenAI 也在同期入场：Codex CLI 在 2025 年 4 月推出，Codex 网页版在 5 月上线，随后铺到 IDE 和 GitHub。

这一阶段的局限也明显：**终端是程序员的主场**，普通人几乎无法进入。

## 二、第二阶段：OpenClaw，Agent 走出终端

### 它是怎么来的

OpenClaw 最初叫 Clawdbot，2025 年 11 月出现。名字是个谐音梗，结合了 Claude 和龙虾螯（claw）。2026 年 1 月 27 日，项目因名称与 Claude 过于相似，在收到 Anthropic 的商标提醒后改名 Moltbot，1 月 30 日定名 OpenClaw。

作者是一位奥地利开发者，据报道他卖掉自己的公司后，为了排遣空虚重新写代码，借助 AI 辅助做出了这个项目。

有个有趣的细节：官方"设定集"里提到，Claw 本意是爪子，龙虾是 logo，但中文圈就此叫它"小龙虾"，传播效果极佳。

### 它的火爆，火在哪

OpenClaw 是开源、本地优先的 AI 代理与自动化平台，能通过自然语言调用浏览器、文件系统、邮件等工具，去完成整理文档、处理邮件、安排日程这类实际任务。它还支持接入多种聊天应用，所以能成为你的 Telegram、飞书或 WhatsApp 里的"秘书"。

热度数据很惊人：短短三个月，GitHub 星标超过 24 万，被称为开源史上增长最快的项目之一。

我认为它真正的突破有三点：

1. **入口换了**：不用打开 IDE 或终端，在你每天用的聊天软件里发一句话就行。
2. **7×24 小时常驻**：不再是"你坐在电脑前才有用"，而是一个持续在线的数字员工。
3. **模型中立**：有评论指出，它从为特定模型装"钩子"的工具，演变成希望被所有模型使用的开源执行框架。

### 它的门槛与隐患

原版 OpenClaw 靠命令行安装，需要配置 Node.js 22 等环境，对普通用户并不友好。而且一个能操控你电脑、邮箱、文件的 Agent，天然意味着**权限大、风险大、token 消耗也大**，这也是少数派等社区文章讨论"成本焦虑"的原因。

这就为第三阶段埋下伏笔：**需求被验证了，但产品还没做好**。

## 三、第三阶段：大厂入场，"龙虾"变成产品

### 同一天的发令枪

2026 年 3 月 9 日，腾讯 WorkBuddy 和字节 ArkClaw 同日上线，阿里 CoPaw 也已布局在先。随后各家密集跟进：腾讯旗下就有 WorkBuddy、QClaw 等多个产品，字节有 ArkClaw，智谱有 AutoClaw，月之暗面有 Kimi Claw，阿里云有 CoPaw、JVSClaw、QoderWork，百度、讯飞也各有产品。

### 三条技术路线

第三方梳理大致分成几类：

- **云端托管 SaaS**：把运行环境、模型、数据全放厂商云端，注册即用，代表是 KimiClaw、ArkClaw。有评测指出，这两者只支持云端部署，且与自家平台强绑定，并非独立产品。
- **一键部署 / 云服务器版**：保留一定控制权，代表是 CoPaw 等。
- **本地桌面客户端**：数据在你自己的电脑上，代表是 WorkBuddy。

### "龙虾"不等于 OpenClaw 套壳

这点常被误解。WorkBuddy 脱胎于腾讯自家的 CodeBuddy，基于腾讯自研的智能体架构，据称马化腾把它称为"自研虾"。它的特点是兼容 OpenClaw 的技能生态，但并非 OpenClaw 的套壳。阿里的 QoderWork 同理，源自原有的 Qoder。

换句话说：**OpenClaw 验证了市场，大厂用自己的工程能力和生态把它"产品化"**。

### 同一家公司也分工

腾讯这个例子很典型。QClaw 主打通过微信远程控制本地电脑，更像"遥控器"；WorkBuddy 专注办公工作流，更像"数字员工"。再看字节 ArkClaw，则瞄准自媒体、MCN 机构，覆盖从监控、抓取、整理到发布的内容流程。

可见大厂不是单打独斗，而是把智能体**嵌进自己已有的社交和办公生态**：腾讯有微信、企业微信、腾讯文档、会议，字节有飞书、内容平台，阿里有云与钉钉。

### Anthropic 这边的对应动作

站在我们自己的产品线看，Claude Cowork 走的是同一方向：把 Claude Code 里验证过的 Agent 能力，带给不写代码的知识工作者，作为面向非开发者的桌面应用。可以看出，**从开发者到普通人，是所有 Agent 厂商的共同选择**。

## 四、门道：这场演化背后的五个规律

**1. 底层越来越同质，差异在"最后一公里"。** 模型可切换，Skill、MCP 成为通用语言，护城河不在 Agent 循环本身，而在生态、入口、安全与服务。

**2. 入口决定渗透率。** Claude Code 的入口是终端，OpenClaw 的入口是聊天软件，WorkBuddy 的入口是桌面加企业 IM。谁离用户的日常工作流更近，谁就更容易普及。

**3. 门槛换成了"信任成本"。** 技术门槛被产品化抹平后，新门槛变成：敢不敢把文件夹、邮箱、账号交给它？所以文件夹级授权、高危操作拦截、沙箱隔离成了办公 Agent 的标配卖点。

**4. 商业模式分化。** 有的走积分制，有的走订阅，有的走企业专属环境。仅 WorkBuddy 一个产品，官网活动页与第三方评测给出的价格就不一致，足见定价仍在剧烈调整。

**5. 开源与闭源各取所需。** 开源（OpenClaw、部分国产项目）胜在可控和可审计，闭源产品胜在开箱即用和合规背书。

## 五、冷思考：别被"养虾热"带偏

- **权限与风险成正比。** 越能干的 Agent，越要从最小权限开始，在可回滚的环境里试。
- **评测要警惕。** 很多"横评"来自个人或自媒体，结论常互相矛盾，价格和额度也在变。小范围实测比看榜单靠谱。
- **别为"全能"买单。** 大多数人 80% 的需求，是周报、表格整理、资料调研这类固定动作，选一个把它做稳的就够了。
- **成本要算账。** 长任务、多 Agent 并行会快速消耗 token 或积分，先估算再铺开。

## 六、给不同人的选择建议

| 你是谁        | 思路                                                         |
| ------------- | ------------------------------------------------------------ |
| 专业开发者    | 终端类（Claude Code、Codex）做主力，重在规范沉淀             |
| 极客 / 爱折腾 | OpenClaw 原版，自由度最高，但要自担部署与安全责任            |
| 普通职场人    | 桌面客户端类（如 WorkBuddy）或微信入口类（如 QClaw），先用免费额度试 |
| 内容创作者    | 看云端托管类，贴合内容流程的产品                             |
| 企业 / 团队   | 先问清数据去向、权限审计、私有化与成本，再谈功能             |

## 结语

回头看这三个阶段：**Claude Code 证明了 Agent 能干活，OpenClaw 证明了普通人也想要，各家办公平台则在回答"怎么安全、便宜、省心地给到每个人"**。

产品名会不断更换，真正长期有价值的是两样东西：一是你对"任务该怎么拆、结果该怎么验"的判断力，二是你沉淀下来、能在不同工具间迁移的 Skill 和工作流。
